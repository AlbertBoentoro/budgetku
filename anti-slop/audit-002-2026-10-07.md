### Exact fix per file (layout/CSS only)
- `app/(app)/dashboard/page.tsx` — account grid changed from
  `grid grid-cols-2 gap-3` to `grid grid-cols-1 min-[375px]:grid-cols-2 gap-3`.
  One column at narrow widths (full-width cards at 320px); two columns from 375px up.
  Tailwind v3.4.1 supports the arbitrary `min-[375px]:` variant, so no
  `tailwind.config.ts screens` churn was needed (build confirms it compiles).
- `components/finance/amount-text.tsx` — added `whitespace-nowrap` to the amount span
  (`whitespace-nowrap tabular-nums tracking-tight ...`). The whole currency string
  (sign + `Rp` + digits) is a single text node and now stays on one line as a unit, so a
  negative amount can no longer break its `-`/`Rp`/digits across lines. nowrap is correct
  for every AmountText usage (balance-card xl, account-card, ledger sm) — none of them
  should ever wrap mid-amount, so no regression.
- `components/finance/account-card.tsx` — responsive amount size so long/negative IDR
  fits the narrow two-column cards without clipping: the AmountText keeps `size="lg"`
  (text-2xl) as the single-column default and adds
  `className="min-[375px]:text-base min-[430px]:text-xl"`. At the narrow two-column range
  (375–429px) the amount renders at text-base; from 430px it steps up to text-xl.
  tailwind-merge preserves all three (base + two breakpoint variants) since they target
  different breakpoints (verified via twMerge). No `overflow:hidden`/`truncate` is used,
  so nothing is clipped or hidden; `tabular-nums` retained.

No color/token change. Total BalanceCard stays `size="xl"` (text-4xl) focal point;
account cards remain neutral surface + icon-only accent; spacing/radius unchanged except
the grid column rule. No money value, calculation, data, route, or auth/Supabase change.

### How long / negative IDR now fits (CSS reasoning)
Container is `max-w-md` (448px) centered with PageContainer `px-4` (16px/side); account
`p-4` (16px/side) inside each card. Column inner widths:
- 320px viewport → content 288px → single column, card inner ≈ 256px. Worst case
  `-Rp999.999.999` at text-2xl (24px, tabular) ≈ 180–200px wide → fits 256px with margin.
- 375px viewport → content 343px → two columns, `gap-3` 12px → each col ≈ 165.5px, card
  inner ≈ 133.5px. Amount at text-base (16px): `-Rp999.999.999` (14 chars) ≈ 120–125px →
  fits 133.5px on one line (whitespace-nowrap keeps it intact).
- 390px viewport → content 358px → each col ≈ 173px, card inner ≈ 141px. text-base
  `-Rp999.999.999` ≈ 120–125px → fits with margin.
- ≥430px up to max-w-md cap (content 416px, card inner ≈ 170px) → text-xl (20px)
  `-Rp999.999.999` ≈ 150–155px → estimated to fit 170px.
These are CSS width ESTIMATES (approximate glyph widths, not measured), so they only
suggest the amount should stay on one line without clipping or hiding. They are not proof.
